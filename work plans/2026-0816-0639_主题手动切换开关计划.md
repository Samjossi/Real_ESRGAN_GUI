## 1. 需求来源

用户反馈：深色主题没有入口，不知道怎么开启。经查证，当前主题是**自动跟随操作系统**的（`darkdetect` 检测 + 监听线程实时切换），GUI 内无任何手动切换入口。

用户明确要求：

1. **不再跟随系统**——移除 `darkdetect` 自动检测与监听逻辑。
2. **默认浅色**——首次启动及配置缺失时使用浅色主题。
3. **用户可手动更改**——GUI 内提供切换开关，选择持久化保存。

---

## 2. 现状分析

### 2.1 主题应用机制（`main.py`）

- `REGUIApp.applyTheme(theme: str)`：调用 `qdarktheme.setup_theme(theme.lower() or 'light', additional_qss=...)` 应用主题；Windows 平台额外通过 `DwmSetWindowAttribute` 设置深色标题栏。该函数本身与来源无关，**手动切换可直接复用**。
- 信号 `sigTheme = Signal(str)` 连接到 `applyTheme`（QueuedConnection），供跨线程触发。

### 2.2 启动时的主题决策（`main.py` 的 `main()`）

- `import darkdetect` → `app.applyTheme(darkdetect.theme())`：跟随系统当前主题。
- Windows/Linux 上启动守护线程 `darkdetect.listener`，系统主题变化时 `sigTheme.emit` 实时切换。
- 异常时 fallback 到 `applyTheme('Light')`。

### 2.3 配置读写（`main.py` / `config.ini`）

- 配置存于 `config.ini` 的 `[Config]` 节，键为大小写无关字符串；启动时读入各控件，关闭时 `saveConfig()` 写回全部键。
- 现有键约 20 个（`ResizeMode`、`Model`、`UseWebP` 等），无主题相关键。

### 2.4 UI 结构

三个选项卡：基本设定（`frameBasicConfig`）、高级设定（`frameAdvancedConfig`）、关于（`frameAbout`）。高级设定页左列为下拉/输入控件，右列为复选框列表（`checkUseWebP` … `checkPreupscale`）。

## 3. 改造方案

### 3.1 UI：主题切换控件

**位置**：高级设定页右列复选框区顶部（`rightColumnAdv` 最前面，现有 `checkUseWebP` 之前）。

**控件**：`QCheckBox('深色模式', ...)`，命名 `checkDarkMode`。

- 与右列现有控件风格完全一致，实现最简单（一个布尔值直接映射 Light/Dark）。
- 不引入「跟随系统」第三态——需求明确移除系统跟随。

> 备选：下拉框「外观主题：浅色 / 深色」。预留了未来加「跟随系统」的余地，但当前需求下复选框足够，不采纳。

### 3.2 启动逻辑：移除系统跟随，改为读配置

`main()` 中的主题决策改为：

1. 从 `config['Config'].get('Theme')` 读取（值 `'Dark'` / `'Light'`，缺失或非法时默认 `'Light'`）。
2. 窗口构造后调用 `app.applyTheme(theme)`，并在控件初始化阶段将 `checkDarkMode.setChecked(theme == 'Dark')`。

**删除内容**：

- `darkdetect` 的 import、检测调用、监听线程启动（整段 try/except 移除）。
- 信号 `sigTheme` 及其 `connect`——移除监听线程后不再有跨线程切换主题的需求，勾选事件在主线程直接调用 `applyTheme`。

### 3.3 切换行为：勾选即时生效

`checkDarkMode.toggled` 连接槽函数：

```python
# main.py（示意，非最终代码）
self.checkDarkMode.toggled.connect(
    lambda checked: self.applyTheme('Dark' if checked else 'Light')
)
```

- 立即调用 `applyTheme` 切换，无需重启。
- Windows 深色标题栏逻辑在 `applyTheme` 内已有，自动覆盖。
- 切换不写日志、不弹提示，保持安静。

### 3.4 配置持久化

- `saveConfig()` 的 `[Config]` 字典新增：`'Theme': 'Dark' if self.checkDarkMode.isChecked() else 'Light'`。
- 现有机制为关闭时统一写回，主题沿用同一机制即可，不在勾选时立即写盘。
- `config.ini` 模板补一行 `theme = Light`（现有文件为全小写键名风格）。

### 3.5 依赖清理

- 检查 `darkdetect` 是否仅为本功能引入；若是，从 `requirements.txt`（或等价依赖清单）移除。移除前需 grep 全项目确认无其他引用。
- `qdarktheme` 保留，仍是主题应用本体。

## 5. 风险与注意点

- ⚠️ **切换时机**：`applyTheme` 通过 `qdarktheme.setup_theme` 全局换肤，处理任务运行中切换理论上安全（纯样式表替换），但验证时需覆盖「处理中切换主题」场景。
- ⚠️ **`checkDarkMode` 初始化的信号顺序**：先 `setChecked` 再 `connect(toggled)`，或用 `blockSignals`，避免初始化时多触发一次 `applyTheme`。
- ⚠️ **Windows 标题栏**：`applyTheme` 中 `theme == 'Dark'` 的大小写敏感，传入值固定用 `'Dark'` / `'Light'`，与配置值保持一致。
- ⚠️ 移除 `darkdetect` 后，`except Exception` 兜底逻辑随之删除；若 `qdarktheme` 自身缺失属安装问题，不再静默兜底为 Light。
- 本项目另有「自定义标题栏」相关指南（`协议和指南/自定义标题栏跨项目复用指南.md`），本次改动不涉及标题栏结构，仅沿用现有 Dwm 属性设置。
