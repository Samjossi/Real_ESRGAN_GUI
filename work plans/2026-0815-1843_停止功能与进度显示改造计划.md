> **范围**：`main.py`、`task.py`、`i18n.ini`；`param.py`、`define.py`、`i18n.py` 不动
> **时间**：2026-08-15 18:43（设计）(UTC+8)
> **优先级**：中

---

## 1. 需求来源

用户提出三点改进：

1. **停止功能**：目前只有「开始 / 暂停 / 继续」，处理中途无法取消。
2. **进度条显示进度**：当前把子进程 stderr 逐行刷到日志框（`textOutput`），观感嘈杂；改为进度条直观显示。
3. **图片列表容器**：将待处理的图片列入一个容器，逐项显示处理进度与状态。

---

## 2. 现状分析

### 2.1 进度与输出机制（`main.py`）

- 日志输出：`textOutput`（`QPlainTextEdit` 只读），`writeToOutput` 把 `task.py` 回调的每一行（含 Real-ESRGAN 的 `xx.xx%` 行）追加进文本框，同时写入 `output.log`。
- 总进度条：`progressbar`（`QProgressBar`，0~1000），由共享列表 `progressValue = [当前文件进度0~1, 已完成文件数, 总文件数]` 驱动，带三次方缓动动画（`progressAnimTimer`）。
- 进度更新的触发点很取巧：`writeToOutput` 每次被调用时重新计算总进度。也就是说**进度刷新依赖于日志行回调**。

### 2.2 任务机制（`task.py`）

- `taskRunner` 在工作线程中从 `queue`（`deque`）逐个取任务执行；`pauseEvent` 只在**任务之间**生效，无法中断正在运行的任务。
- `RESPawnTask.run` 内通过 `subprocess.Popen` 启动 Real-ESRGAN，逐行读 stderr 解析百分比写入 `progressValue[0]`。**子进程句柄没有保存到外部可访问的位置**，因此目前无法从外部终止。
- GIF 处理：`SplitGIFTask` 会动态向队列追加 N 个帧级 `RESPawnTask` + `MergeGIFTask`，一个输入文件对应多个子任务。

### 2.3 按钮区

`buttonProcess` 单按钮三态（开始/暂停/继续），位于基本配置页右下（`main.py:227`）。无停止按钮。

---

## 3. 改造方案

### 3.1 功能一：停止功能

**目标**：处理中可随时停止，当前子进程立即终止，队列清空，临时文件清理，界面复位。

**改动点**：

1. `task.py` — `AbstractTask` 增加可取消能力：
   - 新增模块级/注入式 `cancelEvent: threading.Event`（与 `pauseEvent` 同样由 `main.py` 注入 `taskRunner` 和各任务）。
   - `RESPawnTask.run`：把 `subprocess.Popen` 句柄存到 `self.process`；在逐行读 stderr 的循环中检查 `cancelEvent`，置位时调用 `p.terminate()`（超时后 `p.kill()`），随后抛出专用的 `TaskCancelled` 异常。
   - `taskRunner`：每轮循环开头检查 `cancelEvent`，置位则清空队列并结束；捕获 `TaskCancelled` 时走正常收尾（`finallyCallback`），不当作失败。
   - 停止时的清理：当前文件可能留下半成品输出与 `tempfile` 中间文件。`RESPawnTask` 在 `except TaskCancelled` 中删除已知的临时输入/输出文件（复用现有 `os.remove` 逻辑的条件），再向上抛出。
2. `main.py`：
   - 新增 `self.cancelEvent = threading.Event()`。
   - `buttonProcess` 旁新增 `buttonStop`（停止按钮），仅 `processing` 时可用；点击后：`cancelEvent.set()`、`pauseEvent.set()`（防止线程卡在暂停等待）、按钮临时禁用（避免重复点击），写一行「正在停止…」到日志。
   - `onTaskFinally` 中复位 `cancelEvent`、按钮状态与进度。
   - 新增 i18n 字符串：`StopProcessing`（停止）等，补齐 `i18n.ini` 全部语言（参考现有 `StartProcessing` 等条目，非中文语言先给英文兜底或合理翻译）。

**暂停与停止的关系**：暂停状态点停止 = 立即停止（先 `pauseEvent.set()` 放行，再由 `cancelEvent` 终止）。

### 3.2 功能二：进度条替代逐行日志显示

**目标**：处理时不再把 stderr 逐行刷到 GUI 文本框；用进度条显示进度。

**方案**（两级进度条）：

- **当前文件进度条**（新增 `progressbarCurrentFile`）：直接由 `progressValue[0]` 驱动，显示正在处理的这一张图的 0~100%。
- **总进度条**（现有 `progressbar` 保留）：维持现有 `(progressValue[0] + progressValue[1]) / progressValue[2]` 算法与缓动动画。
- 日志文本框处理时**不再逐行刷新**，改为只显示关键节点信息（开始处理某文件、完成、失败原因）；完整 stderr 仍写入 `output.log`，不丢失排障能力。

**改动点**：

1. `task.py` — 解耦进度上报与日志回调：`RESPawnTask` 解析到百分比时，除写 `progressValue[0]` 外，新增可选回调 `progressCallback(fraction)` 直接上报；不再依赖「日志行触发进度刷新」这条隐式链路。
2. `main.py`：
   - 新增信号 `sigFileProgress(float)`（跨线程，QueuedConnection），槽函数更新当前文件进度条。
   - `writeToOutput` 中增加过滤：来自子进程百分比的行（`\d+[.,]\d+%`）不进 `textOutput`，只进日志文件。其余关键行保留。
   - 总进度的刷新触发点从「每行日志」改为 `sigFileProgress` 与任务完成回调，动画逻辑不变。

> 注：底层 Real-ESRGAN 的百分比本来就来自 stderr 逐行解析，方案只是不再把这些行**显示**到 GUI，解析照旧。

### 3.3 功能三：图片列表容器

**目标**：开始处理后，把本次要处理的图片列入容器，逐项显示状态与进度。

**UI**：基本配置页下方、日志框上方新增 `QTableWidget`（或 `QTreeWidget`，为 GIF 子项留余地，倾向 `QTreeWidget`）：

| 列 | 内容 |
|:---|:---|
| 文件 | 输入文件名（相对路径/基名） |
| 状态 | 等待中 / 处理中 / 完成 / 失败 / 已停止 |
| 进度 | 该行内嵌 `QProgressBar`（`setCellWidget`），0~100% |

**数据模型**：

- `main.py` 在 `buttonProcess_click` 组建任务队列时，为每个输入文件分配 `itemId`（行号），填充列表。GIF 的帧级子任务继承同一 `itemId`（`SplitGIFTask` 已能拿到队列，追加任务时透传），即 GIF 在列表里仍是**一行**，进度为帧聚合值，保持简单。
- `task.py` 各任务构造函数增加可选参数 `itemId: int | None = None`；`RESPawnTask` 的 `progressCallback` 携带 `itemId`。
- `main.py` 新增信号 `sigItemState(itemId, state)` 与 `sigItemProgress(itemId, fraction)`：
  - 任务开始 → 该行「处理中」；
  - 百分比上报 → 更新行内进度条；
  - 完成/失败/停止 → 行状态与进度条着色（失败红、停止灰，用 QSS `QProgressBar::chunk` 区分，沿用现有 accent QSS 机制）。

**与总进度的关系**：列表行进度 = 各文件的 `progressValue[0]` 等价物；总进度条逻辑不变，两套显示同源。

### 3.4 停止后的列表表现

- 处理中的行 → 「已停止」，等待中的行 → 标为「未处理」或整体清空（倾向保留列表并标记，便于用户看到哪些没做完）。
- 下次点击开始时列表清空重建。

## 5. 风险与注意点

- ⚠️ **线程安全**：工作线程 → GUI 一律走信号（QueuedConnection），禁止直接在 `task.py` 触碰控件。
- ⚠️ **停止时的临时文件**：`RESPawnTask` 多级放大链路（`temp0/temp1`）与 pre-upscale 临时文件需尽力清理；清理失败只写日志，不阻断收尾。
- ⚠️ **`progressValue` 共享列表**目前由 GUI 读、工作线程写，原代码即如此（GIL 下标量赋值安全）；本次不重构该机制，仅新增信号通道。
- ⚠️ GIF 聚合进度：帧任务动态追加，`progressValue[2]` 现有 `+= 1` 逻辑保持不动，列表行进度另算（已完成帧数/总帧数需 `SplitGIFTask` 记录帧数后透传）。
- 非中文 i18n 翻译质量：先给合理直译，后续可由母语者校对。
