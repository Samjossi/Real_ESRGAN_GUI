## 3. 方案设计

### 3.1 目标目录结构

```
Real_ESRGAN_GUI/
├── core/                      # Python 源码（新）
│   ├── main.py               # GUI 主入口
│   ├── task.py
│   ├── define.py
│   └── param.py
├── bin/                      # 推理引擎二进制（新）
│   └── realesrgan-ncnn-vulkan
├── models/                   # 模型权重（不动）
├── asset/                    # 图标与打包配置（不动）
├── config.ini
├── pyproject.toml
└── …（治理与文档类文件不动）
```

说明：`core/` 不加 `__init__.py`、不改包名——四个模块相互用 `import define` / `import param` 裸导入，以脚本方式运行（`python core/main.py`）时 `core/` 自动入 `sys.path`，导入逻辑零改动；PyInstaller 入口指向 `core/main.py` 同理。不引入 `python -m` 包式运行，避免相对导入改造。

### 3.2 引用修改细则

- `core/define.py`（核心改动，唯一需要动逻辑的 Python 文件）：
  - 开发态 `BASE_PATH`/`APP_PATH` 改为项目根，即 `os.path.dirname(os.path.dirname(os.path.realpath(__file__)))`；打包态（`_MEIPASS`）分支不变。
  - `RE_PATH` 探测增加 `bin/` 候选：依次尝试 `APP_PATH/<name>`、`APP_PATH/bin/<name>`。打包产物中引擎仍与 exe 同级（macOS spec 打包目标目录保持 `'.'`），旧布局与新布局均可命中。
  - `APP_CONFIG_PATH` 不变（跟随 `APP_PATH`，仍指向项目根 `config.ini`）。
- `core/main.py`、`core/task.py`、`core/param.py`：不改代码。
- `asset/packaging/realesrgan-gui.spec`：Analysis 入口 `['main.py']` → `['core/main.py']`。
- `asset/packaging/realesrgan-gui-macos.spec`：入口同上；二进制探测改 `bin/realesrgan-ncnn-vulkan`（打包目标仍为 `'.'`，产物内布局不变）。
- `asset/packaging/build-macos-app.sh`：下载解压后将二进制移入 `bin/`（`mkdir -p bin && mv …`），后续 `ditto`/`chmod` 路径同步加 `bin/` 前缀。
- `asset/packaging/macos-build-script.sh`：审查同类假设并同步修正。
- `常用命令.md`：`uv run main.py` → `uv run core/main.py`。
- 全文 grep 普查 `main.py`、`realesrgan-ncnn-vulkan` 在 `README.md`、`文档/`、`协议和指南/` 中的残留引用并修正。
- `AGENTS.md`：补充 `core/`、`bin/` 目录说明，更新启动命令。

### 3.3 迁移方式

一律使用 `git mv` 保留文件历史；改完引用后运行冒烟验证。

## 5. 风险与注意点

- ⚠️ `define.py` 的路径基准是整个项目的锚点，开发态/打包态两套分支都要改对，改错会导致引擎找不到、配置写丢、图标丢失；T6 冒烟验证逐项确认。
- ⚠️ Windows `.spec` 不打包引擎与 models（用户自行放置于 exe 同级），`RE_PATH` 双候选探测保证新旧布局均兼容，不回退该行为。
- ⚠️ macOS 打包流程本机无法实跑验证，`.spec` 与 build 脚本只做静态路径一致性核对，实际打包需用户在对应平台执行。
- 🟢 启动方式变化：`python main.py` → `python core/main.py`，用户习惯与文档同步更新。
- 🟢 `__pycache__/` 已在 `.gitignore`，迁移后旧缓存自然失效，无需处理。
- 🟢 `uv.lock`/`pyproject.toml` 无入口脚本声明，不受影响。
