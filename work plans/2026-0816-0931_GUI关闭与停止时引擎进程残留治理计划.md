# GUI 关闭与停止时引擎进程残留治理计划

> **状态**：已实施并验证（2026-08-16，退出链路测试 16/16 通过 + 全量冒烟回归 35/35 通过，待用户真机终裁收口）
> **范围**：`core/main.py`（窗口关闭、停止按钮、日志文件）、`core/task.py`（子进程取消链路）
> **时间**：2026-08-16 09:31 (UTC+8)（设计）/ 2026-08-16 09:36（实施）
> **优先级**：高

---

## 1. 问题来源

用户现场（2026-08-16 凌晨）：处理大图期间点击「停止」甚至直接关闭 GUI 窗口后，引擎子进程 `realesrgan-ncnn-vulkan` 仍在后台全核满载继续跑，GUI 进程也未退出。即**没有完善的退出机制**。

## 2. 现状取证（代码层面）

### 2.1 关闭窗口完全不管处理链路

`core/main.py` `closeEvent` 只做 `saveConfig()` 就放行关闭：

```python
# core/main.py
def closeEvent(self, event):
    self.saveConfig()
    super().closeEvent(event)
```

窗口关闭时：

- ❌ 未置位 `cancelEvent`——工作线程 `taskRunner` 感知不到该停；
- ❌ 未 terminate 引擎子进程——引擎成孤儿进程继续跑；
- ❌ 未 join 工作线程（且线程非 daemon）——窗口关了，Python 进程仍活着；
- ❌ 未关闭 `logFile`——缓冲日志丢失。

### 2.2 停止按钮的取消检查有延迟盲区

`core/task.py` `RESPawnTask.run` 的取消检查嵌在 stderr 逐行读取循环里：

```python
# core/task.py
for line in p.stderr:            # 阻塞等下一行
    if self.isCancelRequested(): # 只有新行到达才有机会检查
        p.terminate()
        ...
```

引擎在 CPU（llvmpipe）上跑大图时 stderr 长时间无输出，用户点「停止」后**要等引擎吐出下一行日志才生效**，体感就是"点了没反应、进程还在跑"。

### 2.3 日志缓冲加剧排查难度（关联缺陷）

`core/main.py` 以默认缓冲打开 `output.log`，处理中途（包括卡死、被杀）磁盘上始终是 0 字节，现场证据全丢。

## 3. 治理方案

### 3.1 关闭窗口 = 完整停机（核心修复）

`closeEvent` 改造为：

1. 若 `self.processing` 为真，先弹确认框「正在处理中，确定退出并终止处理？」（避免误触关窗丢任务）；
2. 确认后：置位 `cancelEvent`、放行 `pauseEvent`；
3. **立即 terminate 当前引擎子进程**（不等 stderr 循环自然走到取消检查，见 3.2 的进程句柄登记）；
4. `join` 工作线程（带超时，超时后日志记录即可，不阻塞关窗）；
5. 关闭 `logFile`；
6. 以上全部尽力而为（try/except 包裹），任何一步失败不阻断关窗。

### 3.2 引擎子进程句柄登记，停止即时生效

- `taskRunner` 已有 `taskStartCallback` 钩子，GUI 侧借此把当前任务对象存到 `self.currentTask`；
- `buttonStop_click` 与 `closeEvent` 停机时，除置位 `cancelEvent` 外，直接对 `self.currentTask.process` 调 `terminate()`（超时 `kill()`），取消延迟从「等下一行日志」降为「立即」；
- `core/task.py` 循环内现有检查保留，作为兜底。

### 3.3 日志改行缓冲

`core/main.py` 打开日志改为 `open(self.logPath, 'w', encoding='utf-8', buffering=1)`，处理中途日志实时落盘；配合 3.1 的关窗前 `close()` 兜底。

### 3.4 工作线程守护化兜底

工作线程 `threading.Thread(..., daemon=True)`：即使 3.1 的 join 路径异常，解释器退出时也不会把引擎孤儿留给系统。注意 daemon 化只是兜底，正常路径仍以 3.1 的优雅停机为准。

## 6. 实施记录（2026-08-16 09:36）

### 6.1 代码改动

- `core/main.py`
  - 新增 `self.currentTask`（`taskStartCallback` 登记当前任务）与 `self.workerThread`（工作线程句柄）；
  - 新增 `terminateCurrentEngine()`：直接 terminate（5 秒超时 kill）当前任务的引擎子进程，OSError 不阻断；
  - `buttonStop_click`：置位 `cancelEvent` 后立即调 `terminateCurrentEngine()`，不再等 stderr 循环走到取消检查；
  - `closeEvent`：处理中关窗先弹确认框；确认后依次置位 `cancelEvent`、放行 `pauseEvent`、杀引擎、join 工作线程（10 秒超时）、关闭并置空 `logFile`，全程尽力而为；取消则 `event.ignore()`；
  - 日志 `open(..., buffering=1)` 行缓冲，处理中途实时落盘；
  - 工作线程 `daemon=True` 兜底；`onTaskFinally` 清空 `currentTask`/`workerThread`，`logFile` 关闭后置空并判空保护。
- `core/task.py`
  - `RESPawnTask.run` 与 `CustomCompressTask.run` 在 stderr 循环结束后补判 `isCancelRequested()`：GUI 侧直接 terminate 引擎时循环因 EOF 退出，补判避免把主动停止误报为 `CalledProcessError` 失败。

### 6.2 验证结果

新增 `tests/exit_chain_test.py`（offscreen 真实跑引擎），16/16 通过：

- E1 中途停止：引擎进程 0.0s 内被回收（修前要等 stderr 新行），无临时文件残留；
- E2 处理中途 `output.log` 已落盘 853 字节（修前为 0 字节）；
- E3 处理中关窗（确认）：引擎回收、工作线程退出、日志正常关闭、无残留；
- E4 处理中关窗（取消）：确认框弹出、关窗被拦截、处理继续。

全量回归 `tests/smoke_test.py` 35/35 通过，原有暂停/继续/停止场景无回归。
