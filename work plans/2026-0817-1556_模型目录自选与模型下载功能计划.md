## 1. 需求来源

用户需求（原话整理）：

1. 程序刚安装时没有模型，此时引导用户选择一个目录，把模型拉取（下载）到该目录；
2. 模型路径改变后程序要能用——用户可以手动调整定位到新目录，重新连接该目录下的模型；
3. 上述配置全部持久化，重启后保持。

本计划是 Windows 分发的前置依赖：打包版不内置模型（减小体积），首次启动靠本功能拉取。

## 2. 现状核查（已读代码确认）

| 项 | 现状 |
|:--|:--|
| `config.ini` | 已有 `modeldir = ` 配置项，当前为空 |
| `core/main.py` `init_config_and_model_paths()` | 已支持 `ModelDir`：非空用配置值，为空回退 `define.APP_PATH/models` |
| `core/main.py` `saveConfig()` | 已把 `ModelDir` 写回 `config.ini`，持久化通道现成 |
| GUI 入口 | ❌ 没有任何修改 `ModelDir` 的界面入口，用户只能手编 `config.ini` |
| 模型列表刷新 | ❌ 模型仅在启动时扫描一次，运行中改目录不会重扫 |
| 缺模型时的行为 | 🔴 启动直接弹警告框 + 打开浏览器下载页 + `sys.exit(0)`，用户自助门槛高 |
| 下载能力 | ❌ 全项目无下载代码；`requirements.txt` 无 `requests` 等网络库 |

结论：持久化与读取链路已通，缺的是 **GUI 入口、运行时重扫、首启引导与下载器** 四块。

## 3. 目标

- 高级设定页新增「模型目录」配置行：显示当前目录 + 「浏览…」按钮 + 「重新扫描」按钮，改动即时生效并持久化；
- 启动检测不到任何模型时，不再直接退出，改为弹出「模型下载引导」对话框：选择存放目录 → 勾选模型 → 下载（带进度）→ 完成后自动扫入并进入主界面；也允许「跳过，稍后手动放置」；
- 下载器仅依赖标准库（`urllib.request` + `zipfile` + `hashlib`），不新增第三方依赖；
- 全部改动对现有「程序同级 `models/`」布局零影响：目录存在且有模型时，启动行为与现在完全一致。

## 4. 设计要点

### 4.1 模型目录修改与重连（GUI 入口）

- 位置：`core/main.py` 高级设定页右栏，「深色模式」上方新增一行：`QLineEdit`（只读展示当前模型目录）+「浏览…」+「重新扫描」两个 `QPushButton`；
- 「浏览…」走 `QFileDialog.getExistingDirectory`（项目已有同款用法，输出目录选择）；
- 选定后：写入 `self.config['Config']['ModelDir']` → 调用重扫 → 刷新 `comboModel` 与 `self.modelFactors` → `saveConfig()` 落盘；
- 「重新扫描」按钮覆盖用户手动往目录里拷贝模型的场景；
- 重扫函数：把 `init_config_and_model_paths()` 中模型扫描段抽成 `scan_models(modelDir) -> list[str]`，启动与运行中共用，避免逻辑分叉；
- 处理中（`self.processing` 为真）禁用该行的控件，防止任务运行中换目录导致引擎 `-m` 参数指向失效。

### 4.2 首次启动下载引导

触发条件：`init_config_and_model_paths()` 返回的 `models` 为空（引擎缺失仍走原有警告逻辑，不在本期改）。

对话框流程：

1. 目录选择：默认 `define.APP_PATH/models`，可改到任意位置（如用户文档目录）；Windows 打包版场景下默认可选到用户目录，规避 Program Files 只读问题（与 `2026-0817-1557_Windows打包适配计划.md` 衔接）；
2. 模型清单：内置一份「推荐模型清单」（名称、文件名、官方来源 URL、体积、SHA-256），首版只列当前项目已用的 6 个模型，避免维护第三方镜像；
3. 下载：勾选模型 → 逐一下载到所选目录 → 进度条 + 当前文件名 + 可取消；
4. 完成后自动重扫，扫到模型才允许关闭对话框进入主界面；「跳过」按钮随时可用（后果是主界面模型下拉为空，重扫后可恢复，不锁死）。

### 4.3 下载器实现

- 新文件 `core/download.py`：`download_file(url, dest, progress_cb, cancel_event) -> None`，`urllib.request.urlopen` 分块读（64 KB），写 `dest.part` 临时文件，完成后 `os.replace` 原子改名；
- 校验：清单内置 SHA-256，下载后比对，不符删除并报错；
- 失败处理：网络异常给出明确错误文案（超时/断连/HTTP 码），单个模型失败不阻断其余；重试交给用户（重新勾选下载），不做自动重试与断点续传（控制复杂度）；
- 若模型来源是 zip 压缩包（官方便携包），用 `zipfile` 解出所需 `.bin/.param`；若来源是直链文件则直接落盘。具体 URL 与形态在 T1 调研后固化进清单；
- 下载在后台线程执行，UI 线程只收进度回调，与 `core/task.py` 现有「工作线程 + 信号回调」模式一致。

### 4.4 持久化

- 复用现有 `saveConfig()` → `config.ini` 的 `ModelDir`，不新增配置项；
- 启动时校验 `ModelDir`：目录不存在或扫不到模型 → 回退默认 `APP_PATH/models` 再扫一次，仍无模型才弹下载引导；回退时清空非法值避免反复踩坑；
- 下载引导中选择的目录同样写入 `ModelDir`，下载完成即完成持久化。

## 6. 回退预案

改动集中在新增文件 `core/download.py` 与 `core/main.py` 的增量段落。回退 = 删除新文件 + 还原 `core/main.py`，`config.ini` 里残留的 `modeldir` 值对旧代码无害（旧版本来就认这个键）。

## 7. 明确不做（本期范围外）

- ❌ 不做断点续传、多线程分块加速、自动重试；
- ❌ 不做模型市场/在线模型列表（清单硬编码，跟随版本发布更新）；
- ❌ 不改引擎缺失时的处理逻辑（仍弹警告指向官方 release）；
- ❌ 不引入 `requests` 等第三方网络库；
- ❌ 不删除「模型放在程序同级 `models/`」的既有兼容行为。

## 8. 风险与未确认项

- ⚠️ GitHub release 直链在国内网络环境可达性差，可能导致下载失败率高。缓解：错误文案中给出手动下载指引（浏览器打开 + 放到已选目录 + 点重新扫描），必要时后续再考虑镜像源；
- ⚠️ 模型清单的 SHA-256 需要随官方版本更新维护，清单变更必须走 T1 流程实下核对；
- ⚠️ 用户选择中文/含空格/无权限目录时的健壮性，需在 T4 测试中覆盖；
- 未确认：官方便携包 zip 内模型的具体路径结构（T1 时核实）。
